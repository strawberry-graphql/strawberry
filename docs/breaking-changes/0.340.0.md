# v0.340.0 custom scalar migration

This release removes the deprecated scalar-wrapper API and adds self-contained
custom scalar annotations. It also deprecates `StrawberryConfig.scalar_map` in
favor of passing `scalar_map` directly to the schema constructor, and deprecates
the older `Schema(scalar_overrides=...)` parameter in favor of the same API.

## Removed: scalar wrappers and decorators

Passing a Python type to `strawberry.scalar`, deprecated since
[0.288.0](./0.288.0.md), is no longer supported. The decorator form and
`ScalarWrapper` are also removed. These changes also apply to
`strawberry.federation.scalar`.

Use `Annotated` to attach a scalar definition to its Python type. Every custom
scalar definition must now include an explicit GraphQL `name`.

**Before:**

```python
from datetime import datetime, timezone
from typing import NewType

import strawberry

EpochDateTime = strawberry.scalar(
    NewType("EpochDateTime", datetime),
    serialize=lambda value: int(value.timestamp()),
    parse_value=lambda value: datetime.fromtimestamp(value, timezone.utc),
)
```

**After:**

```python
from datetime import datetime, timezone
from typing import Annotated, NewType

import strawberry

EpochValue = NewType("EpochValue", datetime)
EpochDateTime = Annotated[
    EpochValue,
    strawberry.scalar(
        name="EpochDateTime",
        serialize=lambda value: int(value.timestamp()),
        parse_value=lambda value: datetime.fromtimestamp(value, timezone.utc),
    ),
]


@strawberry.type
class Query:
    @strawberry.field
    def created(self) -> EpochDateTime:
        return EpochValue(datetime(2020, 1, 2, tzinfo=timezone.utc))


schema = strawberry.Schema(query=Query)
```

Fields and arguments using the annotated alias need no scalar map. Declare the
`NewType` separately so type checkers recognize it. Construct values with the
underlying Python type or `NewType`, not the annotated alias. If you do not need
a distinct static type, use `Annotated[datetime, definition]` instead.

Alternatively, keep an existing Python type or `NewType` and register its scalar
definition with `Schema(scalar_map=...)`, as shown below. This avoids changing
annotations throughout your codebase.

## Deprecated: `StrawberryConfig.scalar_map`

Move scalar registrations and overrides from the config to the schema
constructor. The config option still works, but passing a non-empty map to
`StrawberryConfig` now emits a `DeprecationWarning`.

The [v0.288.0 migration guide](./0.288.0.md) recommended
`StrawberryConfig.scalar_map` when moving away from scalar wrappers. If you
followed that guidance, keep your Python types and scalar definitions unchanged:
only move the mapping to `Schema(scalar_map=...)`. You do not need to adopt
`Annotated` to complete this migration.

Given an existing `Query` using `datetime` and this scalar definition:

```python
from datetime import datetime, timezone

import strawberry

epoch_definition = strawberry.scalar(
    name="DateTime",
    serialize=lambda value: int(value.timestamp()),
    parse_value=lambda value: datetime.fromtimestamp(value, timezone.utc),
)
```

**Before:**

```python
from strawberry.schema.config import StrawberryConfig

schema = strawberry.Schema(
    query=Query,
    config=StrawberryConfig(scalar_map={datetime: epoch_definition}),
)
```

**After:**

```python
schema = strawberry.Schema(
    query=Query,
    scalar_map={datetime: epoch_definition},
)
```

The new parameter is keyword-only and is also available on
`strawberry.federation.Schema`. Other `StrawberryConfig` options are unchanged;
keep passing a config if you use them.

## Deprecated: `Schema(scalar_overrides=...)`

Rename the `scalar_overrides` argument to `scalar_map`:

```python
# Before
schema = strawberry.Schema(Query, scalar_overrides={datetime: epoch_definition})

# After
schema = strawberry.Schema(Query, scalar_map={datetime: epoch_definition})
```

Passing `scalar_overrides` emits a `DeprecationWarning`, including when the map
is empty. Existing overrides still work. This applies to both regular and
federation schemas. Use `scalar_map` for both registration and overrides.

For the same mapping key, direct `scalar_map` takes precedence over
`scalar_overrides`, which takes precedence over the deprecated config map.
Explicit alias mappings win over underlying-type mappings; explicit mappings win
over annotated definitions, which win over built-ins. To override built-in JSON,
use `strawberry.scalars.JSON` as the key, not `dict`.

## Schema code generation

Schema codegen now emits `Annotated[object, strawberry.scalar(...)]` aliases for
custom scalars. Replace the placeholder Python type and supply serialization and
parsing functions appropriate to your scalar. These aliases carry their
definitions without separate registration. JSON is imported from
`strawberry.scalars`.

See [scalars](../types/scalars.md) and
[schema codegen](../codegen/schema-codegen.md) for more examples.
